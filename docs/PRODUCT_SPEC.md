# SEA;NIOR 제품 상세 명세서 (PRODUCT_SPEC)

## 1. 제품 개요 및 정체성
- **브랜드명**: `SEA;NIOR` (항상 대문자로 표기)
- **한 줄 정의**: 시니어의 소중한 경험과 재능을 콘텐츠로 만들어 세상과 연결하고, 그 창작 활동이 지속되도록 돕는 플랫폼.
- **창업 배경 (진정성 있는 스토리)**:
  창업자의 아버지는 평생 대형 트럭을 운전하셨고 73세에 처음 그림을 시작했습니다. 자녀의 도움으로 유튜브 ‘할배의 그림’ 채널에 영상을 올렸을 때 200명 이상의 구독자와 응원, 그림 구매 문의를 받으며 큰 활력을 얻었습니다. 그러나 자녀가 바빠져 편집을 돕지 못하게 되자 업로드가 중단되었습니다. 이 경험에서 **“시니어에게 복잡한 영상 편집을 배우게 하지 말고, 선택하고 이야기하고 확인만 하면 콘텐츠 활동을 지속하게 하자”**는 핵심 솔루션이 도출되었습니다.

## 2. 타깃 페르소나 및 핵심 문제
- **초기 핵심 타깃**: 그림, 공예, 요리, 악기 연주, 원예 등의 재능과 삶의 이야기를 가진 61~74세 액티브 시니어.
- **디지털 숙련도**: 스마트폰, 카카오톡, 유튜브 시청은 익숙하지만 자막 넣기, 썸네일 제작, 영상 편집 앱, 인스타그램 릴스/유튜브 쇼츠 업로드에는 큰 어려움을 겪음.
- **핵심 페인포인트 (Pain Point)**:
  “작품과 이야기는 풍부하지만 편집과 게시의 장벽에서 멈춘다. 자녀나 주변의 도움이 끊기면 활동도 함께 중단된다.”

## 3. 핵심 UX 흐름 (3-Step Mental Model)

```
[고르GO] 사진/영상 선택 → [말하GO] 이야기/분위기 전달 → [콘텐츠 초안 제작] → [확인하GO] 검토 및 수정 → [최종 승인] → 개인 SNS 공유
```

1. **고르GO (선택)**: 스마트폰 앨범에서 사진(JPG, PNG, WEBP) 또는 짧은 영상(MP4)을 선택 (최대 3MB, 고유 스토리지 저장).
2. **말하GO (표현)**: 작품 제목(최대 80자)과 이야기(최대 2,000자)를 텍스트 또는 음성(STT)으로 전달하고, 5가지 표현 스타일(AI 추천, 감동적으로, 따뜻하게, 전시 느낌, SNS 스타일) 중 선택.
3. **확인하GO (검토)**: 제작된 콘텐츠 초안(자막 대본 및 편집 파일)을 확인하고, 필요 시 구체적인 수정 요청을 하거나 최종 승인을 확정.

## 4. 확정 구현 범위 vs 미검증 가설/후속 개발 범위

### A. 이번 필수 구현 완료 범위
- 반응형 웹 (모바일 390px 앱 감성 + 데스크톱 1440px 랜딩)
- 콘텐츠 제작 건 중심의 전체 CRUD
- Supabase Postgres DB 및 Storage 비공개 버킷(`seanior-media`) 연동
- 서버 전용 관리자 클라이언트 (`server-only`, 환경 변수 은닉)
- 서버 측 Zod 검증 및 파일 매직 바이트(Magic Bytes) 위조 검사
- 4단계 상태 전이 및 낙관적 동시성 락(`updated_at` 기반)
- 시니어 접근성: 56px 고대비 버튼, 한글 가독성 최적화, 음성 입력(STT) 버튼

### B. 미검증 가설 및 후속 개발 계획 (현재 범위 제외)
- **월 9,900원 구독제**: 초기 가격 가설이며 실제 결제 시스템은 미연결
- **AI 자동 영상 생성 API**: 외부 AI 엔진 연동은 후속 단계로 분리 (현재는 운영자/검증용 결과 등록)
- **SNS 자동 게시 API**: 외부 인스타그램/유튜브 API 직접 게시는 후속 단계로 분리 (승인이 곧바로 외부 게시를 뜻하지 않음)
- **사용자 로그인 및 개인별 RLS**: 코드잇 미션 7에서 구현 예정 (현재는 공개 테스트 데모)

## 6. 상태 전이 라이프사이클 및 불변 규칙

1. **신규 등록** $\rightarrow$ `submitted`
2. **제작 결과(소개글/파일) 등록** $\rightarrow$ `ready` (이전 승인은 해제)
3. **수정 요청 제출** $\rightarrow$ `revision_requested` (사유 필수 입력, 이전 승인은 해제)
4. **결과 재등록/보완** $\rightarrow$ `ready`
5. **최종 승인** $\rightarrow$ `approved` (`approved_at` 기록)
   - **규칙 1**: 결과물(`result_text` 또는 `result_path`)이 전혀 없으면 승인이 원천 차단됩니다.
   - **규칙 2**: 승인 완료 상태라도 원본(제목, 이야기, 스타일, 미디어)을 수정하면 자동으로 승인이 해제되고 `submitted`로 전환됩니다.
   - **규칙 3**: 이전 탭에서 다른 작업자가 내용을 변경한 경우 `updated_at` 검사를 통해 충돌을 감지하고 덮어쓰기를 방지합니다.
